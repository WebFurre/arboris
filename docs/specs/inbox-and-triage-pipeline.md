# Спецификация модуля быстрой корзины (Inbox & Triage Pipeline)

Документ фиксирует детальную архитектуру, алгоритмы, состояние памяти и UX-механики модуля захвата мыслей и их первичной классификации в приложении Arboris.

---

## 1. Проблематика и Anti-Guilt UX

Пользователи с синдромом дефицита внимания и гиперактивности (СДВГ) сталкиваются с двумя критическими барьерами на этапе работы со входящей информацией:

1. **Входное сопротивление (Input Friction):** любая задержка интерфейса (спиннеры, блокировка инпута, требование сразу выбрать категорию или дедлайн) сбивает фокус внимания, в результате чего мысль забывается, а дофаминовый отклик падает до нуля.
2. **Паралич исполнительной функции (Executive Dysfunction):** вид открытого списка с числом «В корзине 54 мысли» мозг воспринимает как непосильную угрозу. Пользователь прогнозирует часы монотонного труда и закрывает приложение.

### Инженерные принципы реализации:
* **Zero Input Lag:** синхронное обновление локального стейта React с моментальной очисткой инпута в том же тике Event Loop. Обращение к дисковой подсистеме IndexedDB вынесено в неблокирующую фоновую микротаску.
* **Слепой сбор (Blind Capture):** сырая запись всегда инстанциируется через фабрику `createInboxItem(title)` с дефолтным типом `'one_off'`, статусом `'inbox'` и нулевыми счетчиками прокрастинации.
* **15-минутный каппинг времени (Sprint Capping):** алгоритм плашки разбора корзины намеренно скрывает общее число элементов N и фиксирует максимальную планку времени на 15 минутах, превращая разбор в безопасный короткий спринт.
* **Инвертированный триаж:** естественный мыслительный поток строится по цепочке: «Что сделать?» (суть и заметка) -> «Что это такое?» (тип) -> «Сколько займет?» (время) -> «Куда прикрепить?» (ветка дерева).

## 2. Архитектура стейт-машины TriageModal

Компонент `TriageModal` инкапсулирует строгую стейт-машину из 4 последовательных шагов. 

### Шаг 1: Суть мысли и контекст
* **Поля:** `editedTitle: string`, `notes: string`.
* **Поведение:**  
  * Поле названия автоматически получает фокус при монтировании.  
  * Поле `notes` мапится на опциональное поле `notes?: string` контракта `BaseNode`.  
  * При изменении `editedTitle` запускается дебаунс-поиск похожих заметок через Dexie.

### Шаг 2: Характер задачи
* **Поля:** `selectedKind: 'one_off' | 'routine' | 'urgent' | 'leisure'`, `deadlinePreset`.
* **Поведение:**  
  * Отображаются 4 визуальные карточки типов с цветовой кодировкой и кратким описанием роли для Диспетчера фокуса.  
  * Для типа `urgent` отображается MVP-панель быстрых сроков (`Сегодня 21:00`, `Завтра 12:00`, `Через 3 дня`, `Конец недели`).  
  * Для типа `routine` активируется уведомительная плашка о базовом недельном цикле бутонов. Полноценная настройка правил расписания делегирована в Epic 4.

### Шаг 3: Оценка длительности (Estimated Duration)
* **Поля:** `selectedPreset: number | null`, `customMinutes: string`.
* **Разделение состояний (Decoupled State Machine):**  
  * Стейт кнопок-пресетов (`5, 15, 30, 60, 120` мин) и стейт текстового поля кастомного ввода полностью независимы.  
  * Клик по кнопке пресета выставляет `selectedPreset = N` и очищает строку `customMinutes = ''`.  
  * Ввод любого символа в текстовое поле парсится регулярным выражением `/\D/g`, сбрасывает `selectedPreset = null` и записывает сырую строку в `customMinutes`.  
  * Итоговое сохраняемое значение вычисляется функцией:  
    `getEffectiveMinutes = () => selectedPreset !== null ? selectedPreset : (Number(customMinutes) || 15)`.

### Шаг 4: Посадка в дерево (Древовидная маршрутизация)
* **Поля:** `selectedParentId: TaskId | null`, `breadcrumbs: Array<{ id, title }>`.
* **Поведение:**  
  * Начальное состояние — корень графа (`selectedParentId = null`).  
  * Пошаговый спуск (Drill-Down) по уровням иерархии: клик по узлу сдвигает фокус на уровень ниже и пушит элемент в массив хлебных крошек.  
  * Клик по хлебным крошкам обрезает массив пути и возвращает отображение дочерних узлов выбранного уровня.  
  * Финальная кнопка «Посадить в дерево» триггерит сохранение в базу данных и переводит статус задачи из `'inbox'` в `'active'`.

## 3. Алгоритм поиска похожих заметок (Obsidian-Style Early Exit)

Поиск предотвращает создание дубликатов в графе без просадки производительности браузера на больших базах данных.

### Спецификация метода `nodesRepository.searchSimilarTasks`:
1. **Дебаунс 250 мс:** сброс предыдущего таймаута при вводе каждого символа. Вызов базы инициируется только при паузе в наборе текста.
2. **Валидация длины:** запросы короче 2 символов не обрабатываются и мгновенно возвращают пустой массив `[]`.
3. **Потоковая фильтрация Dexie:**   
   * Сканирование выполняется внутренним курсором IndexedDB.   
   * Условие фильтрации: исключаются категории (`kind !== 'category'`), архивные карточки (`status !== 'archived'`) и совпадения по подстроке без учета регистра `title.toLowerCase().includes(query)`.   
   * **Ранний выход (`.limit(3)`):** курсор чтения прерывает транзакцию сразу после нахождения 3 подходящих объектов. В оперативную память V8 Heap десериализуются максимум 3 объекта, исключая сканирование тысяч записей.
4. **Визуализация:** карточки отображаются в блоке предупреждения. Интерактивный клик с переходом на узел в Canvas вынесен в спецификацию Epic 2 (US-2.4).

## 4. Контракты данных и схема репозитория

### Интерфейс параметров триажа:

```typescript
export interface TriageTaskParams {
  id: TaskId;
  title?: string;
  notes?: string;
  parentId: TaskId | null;
  kind: Exclude<NodeKind, 'category'>;
  estimatedMinutes: number;
  deadline?: number;              // Timestamp в миллисекундах (Unix Epoch ms)
  rules?: ScheduleRule[];         // Массив правил расписания рутины
}
```

### Мутации при сохранении в репозитории:
* Поля `status: 'active'` и `updatedAt: Date.now()` применяются ко всем типам задач.
* Для `kind === 'urgent'`: устанавливается точный миллисекундный дедлайн (дефолт при отсутствии пресета — `now + 24 * 60 * 60 * 1000`).
* Для `kind === 'routine'`: объект дополняется структурами:
  * `budCluster: { total: 25, bloomed: 0, missedStreak: 0 }` (емкость бутонов и подушка безопасности).
  * `cooldown: { mode: 'auto', cooldownUntil: null }` (таймаут Диспетчера фокуса).
  * `rules: ScheduleRule[]` (базовое еженедельное правило по умолчанию).
