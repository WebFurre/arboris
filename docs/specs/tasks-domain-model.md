# Спецификация доменной модели задач Arboris 🌲

Документ описывает поведение сущностей, жизненный цикл и математику расписания.

---

## 1. Концепция: «Всё есть узел»

На Canvas в PixiJS все элементы визуализируются геометрическими узлами:
* **Категория (`kind: 'category'`):** контейнер ветки. Не имеет дедлайнов и прогресса выполнения, имеет статус `active | archived`.
* **Исполняемая задача (`ActionableTask`):** конкретное действие, попадающее в очередь «Что делать сейчас?».

---

## 2. Матрица типов задач

| Тип | Статус | Дедлайн | Механика |
| :--- | :--- | :--- | :--- |
| **Urgent** | `TaskStatus` | Обязателен | Пульсация при приближении срока. Участвует в расчете свободных дельт окна. |
| **Routine** | `TaskStatus` | Отсутствует | Ветка из 25–30 бутонов, подушка безопасности на 1 пропуск, нечёткие окна повторения. |
| **One-Off** | `TaskStatus` | Отсутствует | Простое закрытие дела (трансформация в плод). |
| **Leisure** | `TaskStatus` | Отсутствует | Ресурсный банк. Автоматически предлагается после серии закрытых рабочих задач. |

---

## 3. Алгоритм подушки безопасности (Grace Cushion)

Проверка запускается в момент схлопывания временного диапазона:
* **Выполнено:** $bloomed = \min(total, bloomed + 1)$, сброс $missedStreak = 0$.
* **Пропуск (первый подряд):** бутоны не опадают, выставляется флаг $missedStreak = 1$, в интерфейсе выводится мягкое ободрение.
* **Пропуск (второй подряд):** опадает ровно один бутон: $bloomed = \max(0, bloomed - 1)$, счетчик сбрасывается в $missedStreak = 0$.

---

## 4. Разрешение конфликтов в календаре: «Камни и Вода»

1. **Камни (жесткие слоты):** задачи с точным временем (`exactTime`) и фиксированным днем (`fromDay === toDay`) занимают ячейки календаря первыми.
2. **Вода (нечёткие интервалы):** задачи с окном из нескольких дней (`fromDay !== toDay`) проверяют доступность слотов внутри диапазона:
   * Задача встает на первый свободный день.
   * Если день занят жестким событием, задача смещается на следующий день внутри своего диапазона.
