# 1. Выбор архитектуры Arboris и клиентской БД

* **Статус:** Принято
* **Дата:** 2026-10-18
* **Контекст:** Arboris проектируется как инструмент для людей с СДВГ и прокрастинацией. Приложение должно открываться мгновенно, не зависеть от интернет-соединения и гарантировать полную конфиденциальность данных без серверов на старте.

## Решение
1. Приложение строится по принципу **Local-First**.
2. В качестве постоянного хранилища данных на клиенте используется **IndexedDB** через типобезопасную обертку **Dexie.js**.
3. Стейт UI и активных сессий управляется через **Zustand**.
4. Синхронизация и бэкапы реализуются через импорт/экспорт изолированных JSON-манифестов.

## Последствия
* **Плюсы:** Нулевой пинг при взаимодействии, нулевая стоимость серверной инфраструктуры, 100% работоспособность оффлайн.
* **Минусы/Риски:** Ограничение размера локального хранилища браузером, необходимость вручную версионировать схемы миграций БД в IndexedDB.
