# 2. Выбор базового стека ядра, рендеринга и стейта

* **Статус:** Принято
* **Дата:** 2026-10-18
* **Контекст:** Проект Arboris требует высокопроизводительного рендеринга интерактивного графа-дерева с семантическим зумом, реактивного локального хранилища и ультралегкого стейт-менеджмента без оверхеда на ререндеры.

## Решение
1. **Графика и холст графа:** `pixi.js` (v8+). Рендеринг через WebGL/WebGPU Canvas для обеспечения 60+ FPS при масштабировании и анимации сотен узлов дерева задач.
2. **Клиентская база данных:** `dexie` + `dexie-react-hooks`. Обеспечивает строго типизированную работу с IndexedDB и нативные реактивные хуки (`useLiveQuery`) для автоматического обновления UI при мутациях данных.
3. **Стейт-менеджмент:** `zustand`. Легковесный стор без бойлерплейта, изолированный от жизненного цикла React-компонентов. Идеален для хранения состояния зума, текущей активной ветки и режимов таймера.
4. **Стилизация и UI:** `tailwindcss` v4 (CSS-first через `@tailwindcss/vite`) + `lucide-react` для легковесных SVG-иконок интерфейса.

## Последствия
* **Плюсы:** Максимальная производительность графики за счет аппаратного ускорения; независимость состояния от DOM-дерева; zero-latency работа интерфейса.
* **Минусы/Риски:** Необходимость синхронизации двух миров — императивного PixiJS Canvas и декларативного React DOM.
